# Architecture changelog

Change-control record for the Controlled Architecture Implementation
Protocol. One entry per change, newest last. Entries are append-only: a
correction is a new entry that references the one it corrects.

Rules that apply to every entry:

- A schema change is always a migration file, never a manual edit.
- Destructive cleanup never ships in the same change as its replacement.
- If a change needs a new architectural decision, it stops and is reported
  under "Open decisions" instead of being decided here.

## Open decisions

Raised by Phase 0. None has been decided or acted on.

| # | Decision needed | Why it cannot be decided silently |
| --- | --- | --- |
| D1 | Which migration mechanism is authoritative from W1-C onward | W1-C must add `recruitment_events` by migration, but schema consolidation is scheduled for W2. The applied history lives in Supabase's migration table; the repository has three unrelated directories and Drizzle's runner has never run here. A migration cannot be written "properly" until one path is named. |
| D2 | Whether Organization identity is resolved before Recruitment identity | The Level-1 recruitment key is `organization + notification number`. 54 of 201 postings sit under bucket organizations and several real bodies have 3–4 rows, so the key is unreliable until organizations are fixed. The protocol's W1-B names recruitments and posts only. |
| D3 | What a row in `recruitments` is allowed to be | 56 of 183 rows are lifecycle events or non-recruitments, and every recruitment mirrors exactly one posting. Whether admit-card and result notices become `recruitment_events` on a parent, and whether admissions and scholarships are in scope at all, changes the W1-B and W1-C designs. |
| D4 | Canonical and indexability of `/jobs?kind=` | The protocol requires query-free canonicals and noindex filters; the Phase 2 specification called the current `kind` filter acceptable. Today it is indexable with a query-string canonical. |
| D5 | Whether the Level-1 key includes year | Adding `year` to a unique index loosens it. It is correct where a body restarts numbering each year and harmful where a mis-parsed year would let a duplicate through. |
| D6 | Source of Post names for W1-E | Only 5 of 201 postings carry extracted post names (7 names in total). Post resolution has nothing to resolve from until extraction exists. |
| D7 | Row-level security on the canonical tables | Outside the protocol's scope, but the `anon` role can write to `recruitments`, `posts`, `positions`, `exams`, `sources` and `source_documents`. Fixing it is a schema change and needs its own migration and approval. |
