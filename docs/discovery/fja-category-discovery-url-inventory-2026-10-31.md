## Source limitations and architecture rules

- The workbook is a verified category/discovery inventory, not a complete crawl of job-detail URLs, pagination, city/district pages, all exam pages or news URLs.
- The workbook notes that FJA declares `sitemap.xml`, `sitemap-general.xml`, `google-news-sitemap.xml` and `biggest/sitemap.xml`. The first two sitemap fetches failed during source research, so complete sitemap enumeration is unverified.
- Pagination patterns were observed (including `/sarkari-naukri/page/N/` and qualification-page pagination), but individual pagination URLs are not enumerated here.
- Sector, geography, qualification, audience, exam-authority and job-type pages overlap. They are cross-cutting discovery dimensions, not mutually exclusive categories or separate job entities.
- FJA's Puducherry source URL is spelled `/puduchhery-government-jobs/`; preserve it exactly in this source inventory.
- Use this inventory to build an intent/taxonomy mapping and JobOye parity matrix. Do not mirror every source URL as an indexable JobOye page without validating distinct intent, live inventory depth, classification confidence, canonical ownership, differentiation and incremental user value.
- FJA is competitive research input only. JobOye's public facts and links must rely on official recruiting-body sources; never expose FJA as the official source.

## Required JobOye disposition for every source URL

For each of the 84 rows, record:
1. Search intent and discovery family.
2. Existing JobOye route, if any.
3. Canonical Recruitment and Post coverage.
4. Classification method, provenance and confidence.
5. Current eligible/live inventory depth.
6. Source, deadline and lifecycle freshness.
7. Content, UX, metadata, schema and internal-link gaps.
8. Canonical, indexability and sitemap decision.
9. Disposition: improve existing / create candidate / defer / exclude.
10. Owner, dependency and acceptance evidence.

## Required execution gates

1. Complete P0 lifecycle, date/freshness and institutional-aggregation provenance investigations before broad category publication.
2. Complete a fresh FJA page-level review including page structure, content, pagination, internal links and visible inventory. This workbook is not a full crawl.
3. Audit JobOye's current routes and database taxonomy; retain the canonical Recruitment Hub `/jobs/{recruitment-slug}` and Post Leaf `/jobs/{recruitment-slug}/{post-slug}` contract.
4. Resolve classification gaps, notably state attribution and qualification evidence, before publishing broad state/qualification pages.
5. Prioritise by user demand, validated inventory, freshness/source trust, differentiation, implementation cost and cannibalisation risk.
6. Pilot one high-value page family; QA server rendering, canonical, metadata, schema, links, sitemap and mobile usability before expansion.
7. Establish Search Console and analytics baselines; report observed outcomes, not assumed ranking gains.
